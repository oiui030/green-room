# 다음 할 일

테스트하면서 빠져 있거나 더 필요하다고 본 것. 위에 있을수록 먼저.

## 빠진 기능

1. **사진 진단.** 서비스의 핵심인데 아직 없다. Pl@ntNet(종 식별)과 Plant.id(건강 진단)는 API 키가 필요하고, 키를 앱에 넣으면 누구나 볼 수 있어서 중간 서버가 있어야 한다. 서버를 어디에 둘지(Supabase Edge Function 등)부터 정해야 한다.
2. **알림.** 지금은 앱을 열어야 할 일이 보인다. 물 줄 날 아침에 알려주려면 푸시 알림이 필요하다. 웹 푸시는 아이폰에서 홈 화면에 추가한 경우에만 된다. 앱으로 감쌀지(Capacitor)와 함께 정해야 한다.
3. **방 사진으로 환경 읽기.** 온보딩에서 햇빛을 직접 고르게 했다. 처음 구상한 "방 촬영"은 비전 모델이 필요해서 1번과 같은 서버 결정에 묶인다.
4. **개구리와 대화.** 도우미는 증상 고르기까지만 된다. 글로 묻고 답하는 대화는 언어 모델과 서버가 필요하다.
5. **구매 연결.** 준비물은 이름만 보여준다. 어디서 살지 연결하려면 제휴처나 검색 링크 방식을 정해야 한다.
6. **기기 간 동기화와 백업.** 데이터가 브라우저에만 있어서 기기를 바꾸거나 저장 공간을 지우면 사라진다. 계정을 만들지, 내보내기와 가져오기로 갈지 정해야 한다.

## 고칠 것

- **식물 이름 붙이기.** 같은 종을 두 개 등록하면 목록에서 구분이 안 된다. 별명과 놓인 자리를 적게 한다.
- **물 주기 간격 조절.** 간격이 종마다 고정이다. 계절과 방 환경에 따라 사용자가 늘리고 줄일 수 있어야 한다. 겨울에는 자동으로 늘리는 것도 방법이다.
- **잘못 누른 완료 되돌리기.** "줬어요"를 누르면 바로 저장되고 되돌릴 수 없다. 몇 초 동안 "되돌리기"를 보여준다.
- **달력이 이번 주만 보인다.** 다음 주 일정은 목록으로만 나온다. 주를 넘겨 보게 한다.
- **도감이 8종뿐이다.** 종을 늘리고, 이름으로 찾는 검색을 넣는다.
- **도움 요청이 서울만 다룬다.** 다른 지역은 문구 한 줄뿐이다. 사는 곳을 물어 지역별로 안내한다.
- **구조 작전의 날짜.** 단계에 "사흘 뒤" 같은 말만 있고 실제 날짜와 알림이 없다. 시작일 기준으로 날짜를 계산해 달력에 넣는다.
- **온보딩 답 바꾸기.** 햇빛과 돌봄 습관을 나중에 바꿀 설정 화면이 없다.
