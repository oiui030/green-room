# 사진 진단

개구리 대화에서 "사진 찍어 물어보기"를 누르면 사진 한 장으로 종과 건강 상태를 본다.

## 흐름

1. 앱이 사진을 긴 변 1280px JPEG로 줄인다 (보통 150KB 안팎).
2. Supabase 함수 `diagnose`로 보낸다. 앱은 사진을 저장하지 않는다.
3. 함수가 Pl@ntNet(종)과 Kindwise Plant.id(건강)에 묻고 답을 하나로 줄여 돌려준다.
4. 개구리가 종, 의심되는 문제, 이어서 할 일을 말한다. 구조 작전은 사용자가 "구조 작전 시작"을 눌러야 만들어진다.

- 종이 도감 8종 중 하나면 이름을 우리 이름으로 말하고, 등록 안 된 식물이면 등록을 권한다.
- 건강 문제는 우리 구조 작전 5개 중 하나로 옮길 수 있을 때만 작전을 권한다. 곰팡이나 해충처럼 그 밖의 문제는 사람 도움으로 보낸다.
- 확신이 낮으면(종 20% 미만, 문제 25% 미만) 아는 척하지 않는다.

## 서버

- Supabase 프로젝트 `green-room` (서울 리전, 무료 플랜), 함수 `diagnose`
- 소스: `supabase/functions/diagnose/index.ts`
- 주소: `https://gnzewqzybtemkaxrruyd.supabase.co/functions/v1/diagnose`
- 허용하는 곳: `https://oiui030.github.io`, 로컬 개발 주소, iOS 앱. 그 밖의 곳에서 온 요청은 거절한다.
- 한 주소에서 1분에 8장까지, 사진은 2MB쯤까지.

## 켜는 방법 (키 두 개)

Supabase 대시보드에서 green-room 프로젝트의 Edge Functions, Secrets에 넣는다.

| 이름 | 어디서 받나 |
|---|---|
| `PLANTNET_API_KEY` | my.plantnet.org 계정의 API 키 |
| `KINDWISE_API_KEY` | Kindwise(plant.id) 관리 화면의 API 키 |

하나만 넣어도 그 절반은 동작한다. 둘 다 없으면 개구리가 "사진 진단은 아직 준비 중이에요"라고 답하고 증상 고르기로 넘긴다.

Pl@ntNet 키에 도메인이나 IP 제한이 걸려 있으면 서버에서 부른 요청이 거절될 수 있다. 종이 계속 안 나오면 그 설정부터 본다.

## 어디서 되나

- GitHub Pages 주소와 iOS 앱에서 된다.
- claude.ai 테스트 링크에서는 외부 서버 호출이 막혀 있어 버튼을 숨긴다.

## 확인한 것과 못 한 것

- 함수: 배포 후 응답 확인 (인증 없으면 401, 상태 조회 200, 허용 안 된 곳 403).
- 앱: Chrome에서 실제 사진 파일로 줄이기와 전송 확인, 서버 답은 흉내 내어 준비 중, 과습 진단 두 경우 확인.
- 실제 키로 Pl@ntNet과 Kindwise까지 가는 전체 흐름은 아직 한 번도 돌려 보지 못했다. 키를 넣은 뒤 첫 사진에서 응답 형식 차이로 고칠 것이 나올 수 있다.
